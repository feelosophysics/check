# AWS 웹 서버(B6-1), 같이 짚어볼 점

둘 다 서울 리전에 VPC·퍼블릭 서브넷·IGW·라우팅표·보안그룹을 만들고, EC2 한 대에서 Docker로 Nginx를 띄워 브라우저로 접속을 확인했다. 필수 구성은 거의 같으므로, **같은 구성을 어떤 방식으로 만들고 무엇으로 증명했는지**를 중심으로 비교했다. (내 쪽은 과정 순서가 바뀌어 폴더명이 b3-1이다.)

비교 기준: 2026-10-28의 [xifoxy-ru/B6-1 (`ec373a9`)](https://github.com/xifoxy-ru/B6-1/tree/ec373a90854dc2ee834035c60d3ab4f59e172372) · [feelosophysics/codsaid Basic b3-1 (`5b0678a`)](https://github.com/feelosophysics/codsaid/tree/5b0678a5d72b385d4b7095bf92797f6d20263ee8/01_Basic/b3-1).

## 먼저 보는 차이

| --- | --- | --- |

| 삭제 기록 | 자원 ID별 삭제 결과와 단계별 사진 | 삭제 방법 안내, 체크박스는 비어 있음 |
| 자동 테스트 | 가짜 `aws` 명령으로 스크립트를 오프라인 시험 | 없음 |

친구 구현에서는 **재현할 수 있는 배포(User Data·고정된 이미지)**와 **만든 것만 정확히 지우는 정리 절차**가 돋보인다. 내 구현에서는 **HTTPS와 도메인 연결(보너스)**과 콘솔로 구성 요소를 하나씩 익힌 과정을 볼 수 있다. 아래 내용은 두 저장소의 문서·설정·스크립트를 읽고 정리한 것이며, 스크립트를 실행하거나 AWS에서 다시 확인하지는 않았다.

## 1. 요청은 실제로 어떤 길로 들어오는가?

둘 다 그림과 설명에 “IGW → (라우팅표) → 서브넷 → 보안그룹 → EC2” 순서를 적었다. 그런데 **라우팅표는 패킷이 거쳐 가는 장치가 아니라, 서브넷에서 나가는 트래픽의 다음 목적지를 정하는 표**다.

- 들어오는 요청: IGW가 공인 IP를 EC2의 사설 IP로 바꿔 VPC 안으로 넘기고, VPC 안에서는 `local` 경로로 전달된다.
- 나가는 응답: 서브넷에 연결된 라우팅표의 `0.0.0.0/0 → IGW` 경로를 따라 나간다. 이 경로가 없으면 요청은 들어와도 **응답이 나가지 못해** 접속이 안 된다.

내 Mermaid 그림은 `IGW → RT → SG → EC2`로 화살표를 그렸고, 친구 README는 “응답은 서브넷의 인터넷 경로를 따라 돌아간다”고 따로 적었다. 친구 설명이 더 정확하지만, 그림에서는 둘 다 라우팅표를 통과 지점처럼 보이게 했다.

**이야기할 질문:** 라우팅표에서 `0.0.0.0/0 → IGW`를 지우면 브라우저에는 어떤 증상이 보일까? 보안그룹은 들어온 요청의 응답을 왜 따로 허용하지 않아도 될까(상태 저장 방화벽)? 그림에서 라우팅표를 어디에 그려야 오해가 없을까?

## 2. 콘솔로 만들까, 스크립트로 만들까?

친구는 [`create.sh`](https://github.com/xifoxy-ru/B6-1/blob/ec373a90854dc2ee834035c60d3ab4f59e172372/scripts/create.sh)로 VPC부터 EC2까지 순서대로 만들고, 모든 자원에 `Project=B6-1`, `RunId=...` 태그를 붙인다. 눈여겨볼 장치가 많다.

- **계획과 실행 분리:** `--apply`가 없으면 아무것도 만들지 않고 계획 파일만 만든다. 실행할 때 User Data의 해시가 계획과 다르면 멈춘다.
- **중복 생성 방지:** `run-instances`에 `ClientToken`을 붙여, 같은 요청을 다시 보내도 서버가 하나만 생긴다.
- **보안 기본값:** IMDSv2 필수(`HttpTokens: required`), EBS 암호화, 개인키 파일을 `0600`으로 만들고 Git 제외 여부까지 확인한다.
- **결과 불명 처리:** 응답을 못 받은 생성 요청은 다시 보내지 않고 `UNKNOWN`으로 기록해 사람이 확인하게 한다.

대신 비용이 크다. Bash와 `jq`로 쓴 약 860줄은 실습의 학습 목표(네트워크 연결 이해)보다 훨씬 크고, 리뷰어가 읽기 어렵다. 키 저장에 실패하면 [`while :; do sleep 5; done`](https://github.com/xifoxy-ru/B6-1/blob/ec373a90854dc2ee834035c60d3ab4f59e172372/scripts/create.sh#L98)으로 프로세스를 무한히 붙잡아 두는데, 키가 메모리에만 남아 있으니 의도는 이해되지만 처음 보는 사람은 멈춘 것으로 오해하기 쉽다. 실행 폴더명 `excute`는 오타로 보인다.

나는 콘솔에서 하나씩 만들었다. 각 화면이 무엇을 묻는지 직접 보며 익히기에는 좋지만, 같은 환경을 다시 만들거나 “무엇을 만들었는지”를 남기기 어렵다. 실제 설정값도 README 글로만 남아 있다.

**이야기할 질문:** 처음 배울 때는 콘솔, 두 번째부터는 스크립트가 맞을까? 이 정도 규모라면 CloudFormation·Terraform 같은 도구가 Bash보다 나을까? 스크립트의 안전장치 중 꼭 필요한 것 세 가지만 고른다면?

## 3. 서버 설정을 다시 만들 수 있는가?

| | 친구 | 나 |
| --- | --- | --- |
| 설치 방법 | User Data가 첫 부팅 때 자동 실행 | SSH 접속 후 직접 명령 |
| 이미지 | `nginx:1.30.6-alpine@sha256:...` | `nginx:latest` |
| Compose 플러그인 | 버전 고정 + SHA-256 검증 후 설치 | 해당 없음 |
| 재부팅 후 | `restart: unless-stopped`로 자동 재시작 | `--restart` 없음 → 컨테이너가 꺼진 채로 남음 |
| 준비 확인 | `/health` 경로 + healthcheck, 설치 로그에 `BOOTSTRAP READY` | `docker ps`·브라우저 화면 |

`latest`는 받는 날마다 다른 이미지일 수 있다. 오늘 성공한 명령이 다음 달에도 같은 결과를 낸다는 보장이 없다. 친구는 digest까지 고정해 **같은 내용**을 받는다는 것을 보장했다.

나는 EC2를 재부팅하면 웹 서버가 다시 뜨지 않는다. 실습 중에는 문제가 드러나지 않지만, 운영이라면 바로 장애다.

**이야기할 질문:** 버전 태그(`1.30.6`)만 고정하는 것과 digest까지 고정하는 것은 무엇이 다를까? 서버가 재부팅되면 각자의 웹 서버는 어떻게 될까? 수동 설정을 User Data로 옮기면 무엇을 얻고 무엇이 어려워질까(오류를 바로 볼 수 없음 — 친구의 트러블슈팅이 바로 이 경우다)?

## 4. HTTPS: 나만 했지만 아직 남은 일

나는 No-IP 도메인을 EC2 공인 IP에 연결하고, `certbot --standalone`으로 인증서를 받아 Nginx 컨테이너에 마운트했다. HTTP 80은 HTTPS로 301 리다이렉트한다.

같이 볼 빈틈:

- **갱신:** Let's Encrypt 인증서는 90일짜리다. standalone 방식은 갱신할 때도 80번 포트가 필요한데, 그 포트는 Nginx 컨테이너가 쓰고 있다. 갱신 방법(컨테이너를 잠시 멈추기, webroot 방식 등)이 정해져 있지 않다.
- **공인 IP 변경:** 서브넷 자동 할당 IP는 인스턴스를 중지·시작하면 바뀐다. 그러면 도메인이 엉뚱한 주소를 가리킨다. Elastic IP를 쓰면 고정되지만 비용이 따로 든다.
- **문서 불일치:** README에 도메인이 `[여기에 도메인을 입력하세요]`로 남아 있는데, 바로 아래 certbot 명령에는 실제 도메인이 적혀 있다.

친구는 HTTPS를 선택 과제로 남겼다고 밝혔다.

**이야기할 질문:** 인증서 자동 갱신을 이 구조에 넣으려면 무엇을 바꿔야 할까? 도메인을 쓴다면 공인 IP를 어떻게 관리할까?

## 5. 권한: 최소 권한을 어떻게 보여 주는가?

친구는 실제로 쓴 [IAM 정책 JSON](https://github.com/xifoxy-ru/B6-1/blob/ec373a90854dc2ee834035c60d3ab4f59e172372/policies/b6-1-all-in-one.json)을 공개했다. 서울 리전으로 제한하고 필요한 EC2 작업만 나열했지만, `Resource`가 `*`라서 **서울에 있는 다른 EC2도 종료할 수 있다.** 예산·연락처 작업도 같은 사용자에게 붙어 있다. 친구 README는 이 한계를 스스로 적었다.

나는 학습 가이드에 IAM 원리를 길게 정리했고 `Mission-EC2-VPC-Policy`라는 커스텀 정책을 썼다고 적었지만, **정책 내용이 저장소에 없어** 최소 권한인지 다른 사람이 확인할 수 없다.

친구 정책을 좁히는 방법으로는 태그 조건이 있다. 생성할 때는 `aws:RequestTag/Project`를 요구하고, 종료·삭제할 때는 `aws:ResourceTag/Project`가 `B6-1`인 자원만 허용하는 식이다. 친구 스크립트는 이미 모든 자원에 태그를 붙이므로 바로 적용해 볼 수 있다.

**이야기할 질문:** 최소 권한을 “증명”하려면 무엇을 보여 줘야 할까? 정책 문서, 실제로 거부되는 요청, IAM Access Analyzer 결과 중 무엇이 설득력 있을까?

## 6. 문제 해결 보고서와 삭제 기록

**문제 해결.** 친구는 “SSH는 되는데 `/opt/b6-1`이 없다”는 증상을 보고, 재설치하지 않고 cloud-init 상태와 로그로 **설치가 아직 진행 중**임을 확인한 뒤 같은 검증을 다시 실행했다. 실패·준비 완료·성공 화면이 모두 남아 있다. 나는 결제 카드 등록 실패를 기록했다. 실제로 겪은 문제지만 인프라 구성 문제는 아니고, 원인도 “가능성”에 머문다.

**삭제.** 친구는 EC2 → EBS·ENI 확인 → 라우팅 연결·경로 → 서브넷·보안그룹 → IGW·키 → VPC 순으로 지우고, 자원 ID마다 “없음” 응답을 확인했다. **삭제가 끝났다는 것과 청구액이 0이라는 것을 구분**한 점도 좋다. 나는 콘솔 기준 삭제 순서와 이유를 친절하게 설명했지만, 체크박스가 모두 비어 있어 실제로 지웠는지 알 수 없다. 내 안내처럼 콘솔의 “VPC 삭제”는 딸린 자원을 함께 정리해 주지만, CLI는 친구처럼 하나씩 풀고 지워야 한다.

**비용 항목.** 2024년부터 AWS는 공인 IPv4 주소에도 시간당 요금을 받는다. 친구는 비용 항목에 공인 IPv4를 넣었고, 나는 언급이 없다. 무료 사용 조건은 계정 가입 시점에 따라 달라서, 친구처럼 “적용 여부를 확인하지 못했다”고 적는 편이 정확하다.

**이야기할 질문:** 문제 해결 보고서에는 어떤 문제를 골라야 배운 것이 잘 보일까? “다 지웠다”를 다른 사람에게 어떻게 증명할까 — 콘솔 사진, CLI 응답, 비용 화면 중 무엇이 필요할까?

## 7. 문서의 양과 독자

친구 README는 처음에 “결과·제출 자료” 표로 필수 제출물 네 가지를 바로 연결하고, 원문 요구사항별 결과를 접기 블록에 모았다. 다만 본문 곳곳의 `typedNotFound`, `DESTROYED_NOOP`, `UNKNOWN` 같은 스크립트 내부 용어는 스크립트를 모르는 사람에게 어렵다.

내 README는 구성 요소 설명과 단계가 순서대로 이어져 읽기 쉽지만, 앞의 표에서 본 것처럼 설정값과 결과의 **증거**가 약하다. `요성`(요청) 같은 오타도 있다.
