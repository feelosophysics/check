🌳 왜 Tree가 아니라 DAG인가?

일반 트리는 노드가 단 하나의 부모만 가집니다. 하지만 Git은 두 브랜치를 하나로 합치는 머지 커밋(Merge Commit)에서 2개 이상의 부모를 갖습니다. 미래의 작업이 과거를 가리킬 뿐 과거가 미래를 가리킬 수 없으므로 순환(Cycle)이 불가능한 방향성 비순환 그래프(DAG)가 됩니다.

Commit { hash, message, author, timestamp, parents: list[hash] }

🎯 코디세이 미션의 진짜 의도: 4대 핵심 컴퓨터 과학 알고리즘의 융합

LOG (과거 탐색)

부모가 자식보다 항상 먼저 출력되어야 하는 순서 정렬 $ o$ 위상 정렬 (Topological Sort)

PATH (길 찾기)

갈라진 두 브랜치 사이의 최소 변경 단계 탐색 $ o$ 무방향 너비 우선 탐색 (BFS)

SEARCH (검색 엔진)

수만 개 커밋에서 단어를 즉각 찾아내는 인덱스 $ o$ 역색인 (Inverted Index, O(1) 해시)

SORT (수제 정렬)

내장 정렬 금지 제약 하에서 안정 정렬을 직접 구현 $ o$ 병합 정렬 (Merge Sort)

01

PATH 최단경로 & 사전순 타이브레이킹

무방향 간선 모델링: 커밋은 원래 자식 $ o$ 부모 방향이지만, 다른 브랜치 간 이동을 위해 양방향 인접 리스트(`adjacency[h].append(p)`, `adjacency[p].append(h)`) 구축이 필수입니다.

codyssey-b3-2의 그리디 홉 증명: 모든 최단 경로는 홉 수가 같으므로, 앞쪽 노드의 사전순 최소가 곧 전체 경로의 사전순 최소를 보장합니다. 목적지에서 거리를 잰 뒤 거리가 1 감소하는 이웃 중 최소 해시로 전진하여 $O(V+E)$ 단일 패스로 해결합니다.

02

정렬 엔진과 안정 정렬(Stable Sort)

왜 퀵 정렬 대신 병합 정렬인가: 퀵 정렬은 평균 $O(N \log N)$이지만 이미 정렬된 데이터에서 최악 $O(N^2)$로 퇴화합니다. 병합 정렬은 항상 $O(N \log N)$을 보장합니다.

'<=' 연산자의 마법: 병합 단계에서 `left[i] <= right[j]`로 처리함으로써, 키(작성자 이름)가 같은 경우 원래 앞서 생성된 커밋의 순서가 뒤집히지 않는 안정 정렬을 완성합니다.

03

위상 정렬 LOG (부모 우선 출력)

스펙 불변식: 부모가 항상 자식보다 먼저 출력되어야 합니다.

Kahn 알고리즘 진입차수 추적: 부모 방향을 뒤집어 진입차수(In-degree)가 0인 루트 커밋부터 큐에 넣고, 차수를 1씩 차감하며 차수가 0이 된 자식을 큐에 push하는 구조로 시간 무결성을 보장합니다.

04

역색인 SEARCH vs DIFF (LCS)

역색인 트레이드오프: 커밋 시점에 메시지를 토큰화하여 단어장(`by_keyword`)을 구축함으로써, 검색 시 $O(N)$ 전수 조회를 $O(1)$ 해시 조회로 단축시킵니다.

glad의 DIFF 보너스: 동적 계획법(DP) 테이블을 채워 최장 공통 부분수열(LCS)을 역추적함으로써 줄 단위 추가/삭제를 정밀 도출합니다.
